### K-65: A chat key copy from before D-111 can still be moved to another chat

Status: Done in #152: an old copy never seals; a page replaces it first. Found in K-43's fix (#150).

Since D-111 a copy of a chat key names its chat, but `openChatKeyBytes` in `shared/e2ee.ts` still
opens a copy made before, which names none. So someone who writes to the database can take such a
copy from chat X, where a removed member is still a member, and serve it as chat Y's current key
between the same two people. Pages and agents would then seal Y's messages with a key the removed
member holds. D-111's cost line records it.

Fix: a key opened from an old copy never seals; it may still decrypt and go inside a new key's link.
A page gives such a chat a new key that names it before it sends, the way it does after someone
leaves (D-044). An agent never makes keys (D-085), so it waits for a page.
