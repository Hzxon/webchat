### K-61: The pairing poll stops for good on the first failed request

Status: Fixed in #136. Found on 2026-11-07 while reproducing why the Connect coding agent dialog
closed during pairing.

The Connect coding agent dialog looks for the agent's keys with `pairingKeys` every 2 seconds
(`AgentDialog.tsx`, R-030, D-093). The effect's `catch` shows the error and never looks again. One
failed request, such as the `Request failed (502).` while the API restarts in a deploy, or a network
blip, strands the pairing, though the agent may post its keys a moment later.

Fix: a failed request (`ApiError`) shows its error and the poll goes on until the code lapses
(`PAIRING_TTL_MS`). The error `pairingKeys` throws for keys that did not come with the code stays
final: it is a security signal, not a blip.
