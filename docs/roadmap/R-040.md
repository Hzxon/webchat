### R-040: The board is the source of truth, and the repository follows it

Status: Idea. Proposed on 2026-11-07 after the review of #159, and changed the same day after the
owner's review: only the board gives out numbers, and `scripts/claim.sh` stays alongside.

Why: a project's board and its repository's `docs/roadmap.md` and `docs/decisions.md` drift
apart. Only "Copy as Markdown" joins them, by hand (D-082). The board numbers a card from its own
cards, so the board's K-1 in #159 is not the repository's K-1, the reload after a deploy that #6
closed. An agent that greps K-1, as AGENTS.md says, reads the wrong entry. And a card run edits the
repository's docs, which never reach the board.

Scope:

- The project owner links the board to one of the project's repositories. From then on the
  repository's `docs/roadmap.md` and `docs/decisions.md` are copies of the board. Nobody edits them
  by hand.
- The owner's agent writes the copy, because only it can. The server cannot read the board (D-014),
  and the page never holds the GitHub token (rule 8). The agent reads the board as a member and
  pushes with the owner's `gh` (D-092).
- Board doc versions are in the sync fingerprint (D-081), so the agent sees each change. When no
  card has changed for 10 minutes, it renders both columns with `columnMarkdown`. It commits them to
  one branch, `agent/board`, and keeps one draft pull request open on it. It never pushes main and
  never forces (D-092). The owner merges it like any other pull request.
- When the board is first linked, it imports the repository's docs once. The agent sends the parsed
  entries to its owner's page, and the page writes them as cards, since only a page writes the board
  (D-104). Repository entries keep their numbers, because code, commits and decisions cite them. A
  board card whose number is taken moves to the next free number, and its text names the old one.
- Only the board gives out numbers (R-041). Work in the repository proposes changes and never
  writes the copy. A pull request adds a new entry as a file named by a short name, such as
  `docs/roadmap/new-bark-banner.md`, and a change to an entry as a file named by its id, such as
  `docs/roadmap/K-12.md` (D-106). Decisions get the same kind of folder, `docs/decisions/`. Once
  such a file is on main, the agent sends it to the owner's page as a card draft (D-104). The page
  numbers a new card when the owner accepts it. The next `agent/board` pull request then deletes the
  file and writes the card into the copy.
- Sessions outside WebChat still claim with `scripts/claim.sh`, so the two kinds of claim must see
  each other. A run refuses a card that an open pull request names, and opens its own draft when it
  claims (R-042). And when the agent sees an open pull request that names a card, the owner's page
  sets that card to `In progress: repo#N`, as it sets a run's status (D-100).
- A CI check fails a pull request that edits `docs/roadmap.md` or `docs/decisions.md`, unless the
  pull request comes from `agent/board`.
- A board that is linked shows every member the repository its cards go to.

What changes in the process: AGENTS.md stops saying "edit the docs in place". The housekeeping pull
requests of D-076 and D-106 stop, since the agent folds the files. `scripts/claim.sh` still claims
with a draft on GitHub (D-062), but it stops reserving decision numbers with `reserve/D-*` tags. A
session that needs a new decision asks the owner to add it on the board, which numbers it. D-076,
D-082 and D-106 change, and AGENTS.md, `scripts/claim.sh`, `.claude/rules/process.md` and the CI
change with them.

Cost: card text is end-to-end encrypted on the board but plain text in the repository. GitHub and
everyone who can read the repository can read it. The README section "What it does not protect
against" must say so (rule 1). Main lags the board until the owner merges `agent/board`. Nothing
syncs while the owner's laptop is off or its plugin is asleep (D-113). A session outside WebChat
waits for the owner whenever it needs a new number.

Open questions:

- `docs/decisions.md` groups decisions under topic headings, and the board has no topics. Should
  a decision card get a `Topic:` line so the copy keeps them, or should the copy drop them?
- `docs/roadmap.md` lists finished items as one row each in its Done table. Should the copy keep
  writing that table from Done cards, or list each card in full?
- The "How to use this file" text at the top of `docs/roadmap.md` is not a card. Should it move to
  AGENTS.md?
- May one repository be linked from two projects? This proposal refuses a second link.

Done when: the owner links a board to a repository, and the board then shows the repository's
entries with their numbers. An edit to a card leads to an `agent/board` draft whose files match
"Copy as Markdown". A merged `docs/roadmap/K-n.md` reaches the owner's page as a card draft. A pull
request that edits the copy by hand fails CI. The README lists the plain text copy.
