### R-036: One Claude Code window serves every repository, and the agent clones from WebChat

Status: Planned. Decided with the owner on 2026-11-06, in a design session on the agent workflow.
Do after R-037, which is contained; R-038 builds on this.

Why: today the owner connects each repository with `/webchat:connect` in a checkout of it (D-101),
and a Claude Code window must stay open in that checkout for the agent to serve it (D-094). One
open window serves one repository. A student with three projects keeps three windows open, and a
repository that was never cloned on the laptop cannot be worked on from WebChat at all. The owner
wants to pair once, keep one window open anywhere, and let the agent get the rest for itself.

Scope:

- The plugin's server starts in any folder and serves every folder it knows. Its own folder no
  longer matters, so `start` in `agent/plugin.ts` stops refusing a folder that is no GitHub
  repository. One check-in per laptop names every known repository with its state, in place of one
  check-in per repository. The lock moves from the repository to the folder: with two windows open,
  one serves each folder and the other waits, as now.
- A request for a repository with no folder on the laptop answers in the conversation with "I have
  no copy of owner/repo on this laptop." and a **Clone it** button. The page signs a clone request
  the way it signs a prompt (D-102). The plugin's server, never the background Claude, clones with
  the owner's `gh` login into `~/WebChat/<owner>/<repo>`, blobless (`--filter=blob:none`), marks
  the folder connected, says where it put it, and then runs the request that was waiting. It
  clones only on the owner's signed request, only a repository that one of the owner's projects
  links (D-050), and only under that root. The answer says "Cloning owner/repo, this can take a
  while" first, since a clone of a course repository can take minutes.
- `/webchat:connect` stays as an optional command for one case: the owner already has a clone and
  wants the agent to use that folder. It leaves the setup steps in the README. "Forget this folder"
  moves to the pane, and it deletes only the mark, never files.
- The asleep state in the pane says what to do in plain words: keep one Claude Code window open,
  and the laptop awake.
- The server learns that the agent is online whenever any Claude Code window is open, not only in
  a connected repository. It still learns repository names only, never a path. Update the README
  section "What it does not protect against" (rule 1).

Decisions: rewrite D-094 and D-101, and add one decision for the clone root and what may be cloned.
The owner's signed click replaces the prompt that `connect` carries today, with the same guarantee:
a repository's files can never connect themselves.

Done when: on a laptop where the plugin is paired and one Claude Code window is open in the home
folder, a card from a project whose repository was never cloned there reaches "In review" after one
click on **Clone it**. A test covers a clone request that the owner did not sign, and one for a
repository that none of the owner's projects links.
