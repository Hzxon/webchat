### R-042: A card run follows the repository's workflow

Status: Idea. Proposed on 2026-11-07. It builds on R-040, which gives the board and the repository
one set of numbers, and on R-039 and R-041.

Why: the workflow in AGENTS.md works. Each session checks that its item still holds, claims it with
a draft, reserves its decision number, updates the docs with the change, shows its evidence and
waits for the owner. A card run skips most of this, as #159 shows. It took the board's K-1, which
the repository uses for another item. It checked nothing on GitHub, because its shell cannot reach
it. It left 116 tests cancelled. And a session in the repository could not see that the card was
taken.

Each step of AGENTS.md, what a run does today, and the change:

1. Check that the item still holds (D-107). Today the page refuses a card another agent runs
   (K-59), and the agent refuses its own second run (D-099). Nothing checks main, the decisions or
   GitHub. Change: before the turn, the plugin lists with its own `gh` the open pull requests that
   name the card, as `claim.sh` does, and puts them in the brief. The run checks first: is it fixed
   on main, does a decision settle it, does another card or pull request cover it? If the card no
   longer holds, the run ends with the outcome "stale" and the reason, and pushes nothing. The pane
   offers the owner a change of the card's status to Done or Dropped with that reason (D-104).
2. Claim it (D-062). Today the status line says `In progress: Ann's agent`, which only the board
   shows (D-100). Change: once the check passes, the plugin pushes an empty commit and opens the
   draft at once, with the check in its body, as `claim.sh` does. A session in the repository then
   sees the claim among the open pull requests. The plugin refuses a card that an open pull request
   already names.
3. Reserve a decision number (D-076). Today nothing does: the board numbers a decision card only
   when the owner adds it. Change: the run writes a new decision's number as `D-NEXT` wherever it
   cites it. When the run is done, the plugin takes the next number that is free on the board, on
   main and among the `reserve/D-*` tags, and pushes that tag. The remote creates each tag only
   once, so two runs never get one number. The plugin then replaces `D-NEXT` in one more commit and
   pushes the branch.
4. Update the docs with the change. Today the run edits `docs/` on its branch, which never reaches
   the board. Change: with R-040 those files are copies of the board, so the run's answer carries
   board changes instead: its card's status, new decisions, changes to decisions, and a new card for
   each gap it found. The pane shows them under the draft, and the owner adds them. A new decision
   starts as Proposed. When the pull request is merged, the plugin reports it. The owner's page then
   sets the card to Done or Fixed with the pull request number, and its decisions to Accepted, as it
   sets `In review` today (D-100). Lines in `.claude/rules/` stay in the pull request, since they
   are files of the repository.
5. Check before ready. Today the run runs typecheck, tests and build, but the sandbox refuses to
   listen on 127.0.0.1, so the server tests are cancelled, as in #159. Change: the plugin's settings
   set `sandbox.network.allowLocalBinding`, so the whole suite runs. A change people see still needs
   the owner's browser check, and the pull request body says so.
6. Show the evidence and wait for the go. Today this already holds: the run reads AGENTS.md, and
   the plugin opens a draft that only the owner merges (D-092, D-105). R-039 adds the owner's own
   conventions.
7. Close what you abandon. Today a failed run puts the card's status back (D-100). With step 2 it
   would also leave its empty draft open. Change: a run that fails or is cancelled closes its draft
   with a comment that says why.

Three steps need no change. The board folds Done cards by itself, and R-040 writes the copy, so no
housekeeping is needed. The board warns about a repeated number (D-063), and `doc-ids` still checks
the copy. R-041 checks new cards.

Cost: on macOS, `allowLocalBinding` lets sandboxed commands reach every service that listens on the
owner's localhost, such as a local database or a debugger. On Linux it has no effect, since there
each command has its own localhost. A draft opens before any code, so a run that fails leaves a
closed draft behind. A number the model guesses instead of writing `D-NEXT` is caught only when the
board warns about a repeat. This changes D-092, D-097, D-100 and D-104, and it needs R-040 first.
Without one set of numbers, a claim on GitHub names the board's id, which can mean another item in
the repository.

Open questions:

- Should a run stop after the check and wait for the owner's go before it claims, or claim as soon
  as the check passes?
- Should `allowLocalBinding` be a choice in R-039's agent settings, since it widens the sandbox?
- Should the owner's page add a run's board changes when the pull request merges, without a click?
  Merging means the owner saw them, which is what D-104 asks for.

Done when: a run of a card that an open pull request names is refused with that pull request's
number. A run of a card that main already fixed ends as "stale" and offers the status change. A
normal run opens its draft before its first commit of code, runs the server tests, gives each new
decision a reserved number, and moves its card to Done with the pull request number once it merges.
