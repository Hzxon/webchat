### R-042: A card run follows the repository's workflow

Status: Done in #168 (D-118): a run checks its card, claims it with a draft before any code, waits
for a decision nobody foresaw, and on merge its card and decisions follow. Proposed on 2026-11-07,
and changed the same day after the owner's review. It builds
on R-040, where the board is the source of truth, and on R-041, which checks a card when it is made
and numbers it on the board. R-039 brings the owner's own conventions.

Why: the workflow in AGENTS.md works. Each session checks that its item still holds, claims it,
reserves its decision number, updates the docs with the change, shows its evidence and waits for the
owner. A card run skips most of this, as #159 shows. It took the board's K-1, which the repository
uses for another item. It checked nothing on GitHub, left 116 tests cancelled, and a session in the
repository could not see that the card was taken. With R-041 the check and the numbers move to the
board when a card is made, so a run needs only the steps below.

1. Check again that the card still holds (D-107). Code and cards change between a card's check and
   its run. Before the turn, the plugin lists with its own `gh` the open pull requests that name the
   card, and refuses the card when one does, as `claim.sh` does. The run then reads the card's
   `Checked:` line and checks the code, the decisions and the cards as they are now. A card that
   shows as Unchecked gets R-041's full check here. If the card no longer holds, the run ends with
   the outcome "stale" and the reason, and pushes nothing. The pane offers the owner a change of the
   card's status to Done or Dropped with that reason (D-104).
2. Claim it (D-062). In WebChat the claim is the card's status, `In progress: Ann's agent`
   (D-100). Sessions outside WebChat still claim with `claim.sh`, which looks for open pull
   requests (R-040). So once the check passes, the plugin also pushes an empty commit and opens the
   draft, with the check in its body, as `claim.sh` does.
3. Get a decision number from the board. A decision the card needs was drafted with it (R-041), so
   it has a number. When the run finds one nobody foresaw, it pauses. It ends with the outcome
   "decision" and a draft of that decision, and the card's status says `Waiting for a decision`, so
   teammates see why it is held. The owner adds the draft on the board, which numbers it, and sends
   their go. The run then goes on in the same session with that number, as a round of fixes does
   (D-105). The plugin fetches main first and tells the run what moved. The owner gets a reminder
   after a day. After 7 days the run fails and closes its draft, but keeps its branch.
4. Update the board with the change. The repository's docs are copies of the board (R-040), so the
   run's answer carries board changes instead: changes to decisions, and a new card for each gap it
   found. The pull request body lists them too. The pane shows them under the draft, and they wait
   there until the owner adds them, since nothing new reaches the board unseen (D-104). Statuses
   change without a click: when the pull request is merged, the plugin reports it, and the owner's
   page sets the card to Done or Fixed with the pull request number and its decisions to Accepted,
   as it sets `In review` today (D-100).
   Lines in `.claude/rules/` stay in the pull request, since they are files of the repository.
5. Check before ready. This already holds. The run runs typecheck, tests and build, but its sandbox
   cannot listen on 127.0.0.1, so the server tests are cancelled, as in #159. The sandbox stays
   that way: CI runs the whole suite on every pull request, and a failure starts a round of fixes
   by itself (D-105). The pull request body says which tests the run could not run. A change people
   see still needs the owner's browser check, and the body says so.
6. Show the evidence and wait for the go. This already holds: the run reads AGENTS.md, and the
   plugin opens a draft that only the owner merges (D-092, D-105).
7. Close what you abandon. Today a failed run puts the card's status back (D-100). A run that
   fails, is cancelled or ends as "stale" will also close its draft, with a comment that says why.

Three steps need no change. The board folds Done cards by itself, and R-040 writes the copy, so no
housekeeping is needed. R-041's column lock gives each card one number, and `doc-ids` still checks
the copy.

Cost: a draft opens before any code, so a run that fails leaves a closed draft behind. A run that
pauses for a decision keeps its worktree and holds its card for up to 7 days. A server test that
fails shows only in CI, a few minutes after the push. Status changes on merge happen only while a
page of the owner's is open, as today (D-100). This changes D-092, D-100, D-104 and D-105. It needs
R-040 and R-041 first.

Settled in the owner's review: the sandbox stays closed to localhost, since CI covers the server
tests; a paused run waits as above; statuses change on merge without a click, and new content waits
for one.

Done when: a run of a card that an open pull request names is refused with that pull request's
number. A run of a card that main already does ends as "stale" and offers the status change. A
normal run opens its draft before its first commit of code. A run that finds a decision shows
`Waiting for a decision`, and goes on with the number the board gave it. Once the pull request
merges, the card moves to Done with its number and its decisions to Accepted, while new cards from
the run wait in the pane for the owner's click.
