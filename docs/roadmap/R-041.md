### R-041: A card draft is checked against the decisions and the open cards

Status: Idea. Proposed on 2026-11-07.

Why: when an owner asks their agent to draft a card, the draft can repeat a card a teammate added
but nobody has built yet. It can also go against a decision the team holds. Nobody notices until the
card runs or its pull request is reviewed. Two gaps in `converse` in `agent/plugin.ts` cause this:

- A conversation about a project that links a repository gets none of the board's decisions.
  `roadmap()` reads them only when there is no folder, and only on the first turn (R-038). The
  agent can read the repository's `docs/decisions.md`, but it can differ from the board until
  R-040.
- The first brief holds every roadmap card, and a reply holds the cards that changed since. But
  nothing asks the agent to compare a draft with them. And a reply never shows decisions that
  changed.

Scope:

- Every turn reads the decisions the team holds, as `heldDecisions` gives them, with or without a
  repository. A reply shows the decisions that changed since the agent last saw them, as it already
  does for cards.
- The brief tells the agent to compare a draft with every roadmap card and every decision first:
  - If an open card already covers it, the agent drafts a change to that card with `replaces`, or
    names it and drafts nothing. A card is open unless its status is Done, Fixed or Dropped.
  - If a Done or Fixed card covers it, the agent says so.
  - If the draft goes against a decision, the agent names the decision and why. It drafts only when
    the owner still wants it, and the draft's body says which decision it would change.
- The answer's `card` gains `related`: a list of `{ id, kind: 'duplicate' | 'conflict', why }`.
  `draftOf` keeps only ids the brief held, as it already does for `replaces`.
- `AgentDraft` lists each related card or decision above its "Add as" or "Update" button, with the
  reason and a link that opens the card on the board. A conflict with a decision shows as a
  warning. Nothing is blocked: the owner decides.

Constraints: the decisions and cards stay fenced as teammates' text (D-104) and reach the background
Claude only on its stdin (D-097). The draft travels in the owner's encrypted direct chat, so the
server learns nothing new. The page drops a related id it cannot find on the board.

Cost: every turn carries all held decisions, about as long as a card run's brief, which already
holds them (D-105). The check is the model's judgment. It can miss a duplicate written in other
words, or flag one that is not. The pane shows the reason, so the owner can judge it. A card a
teammate adds after the turn is compared only on the next reply. This changes D-104 and the comment
on `roadmap()` that ties decisions to R-038.

Open questions:

- A draft today is only a roadmap card, an idea or an issue. When a draft conflicts with a
  decision, should the agent also draft a change to that decision?
- Should the page warn at the button about cards added since the turn? It cannot judge their
  content, so it could only list them.

Done when: in a project that links a repository, asking for a card that an open card already covers
gets a change to that card, or a reply that names it, not a new card. A draft against a held
decision shows that decision as a warning in the pane. A test checks that a first brief and a reply
both hold the decisions, and that `draftOf` keeps only related ids the brief held.
