### R-041: The agent checks a new card, and the board numbers it

Status: Idea. Proposed on 2026-11-07, and changed the same day after the owner's review. With R-040
the board is the source of truth, so the check that `scripts/claim.sh -c` asks for today (D-107)
moves to the moment a card is made, and only the board gives out numbers.

Why: a new card can repeat a card a teammate added but nobody has built yet. It can go against a
decision the team holds, or ask for what the code already does. Nobody notices until the card runs
or its pull request is reviewed. Three gaps in `converse` in `agent/plugin.ts` cause this:

- A conversation about a project that links a repository gets none of the board's decisions.
  `roadmap()` reads them only when there is no folder, and only on the first turn (R-038). A reply
  never shows decisions that changed.
- The brief holds every roadmap card and a scratch copy of the code (D-102), but nothing asks the
  agent to compare a draft with them.
- The agent cannot see open pull requests, since its shell cannot reach GitHub. Sessions outside
  WebChat still claim items with them (R-040).

Scope:

- Every turn reads the decisions the team holds, as `heldDecisions` gives them, with or without a
  repository. A reply shows the decisions that changed since, as it already does for cards.
- The plugin lists the linked repository's open pull requests with its own `gh` and puts their
  numbers and titles in the brief.
- Before it drafts, the agent checks the draft against four things:
  - The roadmap cards. If an open card covers it, the agent drafts a change to that card with
    `replaces`, or names it and drafts nothing. A card is open unless its status is Done, Fixed or
    Dropped. If a Done or Fixed card covers it, the agent says so.
  - The decisions. If the draft goes against one, the agent names it and why. It drafts only when
    the owner still wants it, together with a change to that decision.
  - The code, in the scratch copy. If the code already does it, the agent says where.
  - The open pull requests. If one covers it, the agent names it.
- A draft can also be a decision: new, or a change to one with `replaces`. When a card needs a
  decision, the agent drafts both, and the decision starts as Proposed.
- The answer's `card` gains `checked`, a line saying what the check read, as `claim.sh -c` records.
  It also gains `related`, a list of `{ id, kind: 'duplicate' | 'conflict', why }`. `draftOf` keeps
  only ids the brief held, as it already does for `replaces`.
- `AgentDraft` lists each related card, decision or pull request, with the reason, above its
  "Add as" or "Update" button. A conflict shows as a warning. Nothing is blocked: the owner decides.
- When the owner adds the draft, the card's text gets a `Checked:` line with the date and the
  check's line. A card without one shows as Unchecked on the board. Anyone can still add a card by
  hand. It stays Unchecked until its owner's agent checks it, and its run checks it first (R-042).
  An edit never takes the mark away. A "Check again" button on a card asks the clicker's agent to
  run the check on the card as it is now. The answer is a draft like any other: a new `Checked:`
  line, or a change, or a reply that names what it found.
- The owner's page gives a new card or decision its number when it adds it, as now (D-104). It
  first takes the lock of the column doc's `title` section (D-081), reads the numbers, saves the
  card, then lets the lock go. Two pages never give one number, which today the board only warns
  about (D-063). Nobody edits a board's title by hand, so the lock blocks nothing else. It needs no
  server change and shows the server nothing new, and a tab that dies holding it loses it after 2
  minutes. A page that finds it held tries again for a few seconds, then says someone is adding a
  card.

Constraints: the decisions, cards and pull request titles stay fenced as teammates' text (D-104),
and reach the background Claude only on its stdin (D-097). The draft travels in the owner's
encrypted direct chat, so the server learns nothing new. The page drops a related id it cannot find.

Cost: every turn carries all held decisions, about as long as a card run's brief (D-105). The check
is the model's judgment, so it can miss a duplicate written in other words, or flag one that is not.
The pane shows the reason, so the owner can judge it. A card a teammate adds after the turn is
compared only on the next reply. A card edited after its check keeps its mark until someone checks
it again, so the mark can be out of date; a run's check covers that (R-042). Two pages adding a
card wait for each other. This changes D-063, D-082 and D-104.

Settled in the owner's review: an edit never unchecks a card, and "Check again" asks for a new
check; numbers come under the column doc's `title` lock.

Done when: in a project that links a repository, asking for a card that an open card covers gets a
change to that card, or a reply that names it, not a new card. Asking for what the code already
does gets a reply that says where. A draft against a held decision shows that decision as a
warning, with a draft change to it. A card that needs a decision comes with a Proposed decision
draft. Two pages that add a card at once give it two numbers. A card added by hand shows as
Unchecked, and "Check again" on it brings back the agent's check as a draft. A test checks that a
first brief and a reply hold the decisions and the open pull requests, and that `draftOf` keeps
only related ids the brief held.
