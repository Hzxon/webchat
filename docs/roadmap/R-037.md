### R-037: An agent runs several cards at once

Status: Done in #130. Decided with the owner on 2026-11-06. The busy flag is gone, and the Coding
agents pane counts the cards that run.

Why: an agent runs one card at a time (D-086, D-099). A second card gets "I am busy with K-2."
Each run already works in a worktree of its own (D-092), so nothing in the checkout stops two runs
from going at once. The limit was a choice, for a busy flag the play menu could show, and the
owner no longer wants it: a student hands the agent several cards and expects them all to start.

Scope:

- `Runs.running` in `agent/runs.ts` becomes a map by card. Each request gets its own worktree and
  its own background Claude session, as now. `recover` reports every run a restart cut short.
- The same card twice is still refused (D-099), since two tabs can each send a request before they
  sync. A request for another card no longer gets "I am busy".
- The busy flag on the account (D-085) means nothing with no limit. Drop it from the play menu and
  from the sync fingerprint (D-021), or make it a count. The Coding agents pane shows how many runs
  are going.
- No cap. The owner accepts the cost: five cards are five sandboxed Claudes on one laptop and five
  drafts pushed with the owner's login.

Decisions: rewrite D-086 and D-099, and the busy line of D-085.

Done when: two cards handed to one agent within a minute both reach "In review" with a draft each.
A test covers a second request for a card that is running, refused, and a request for another card
while one runs, claimed.
