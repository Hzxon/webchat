### D-135: ACP agents run from a shipped list, one process for each session

Status: Proposed 2026-11-13 in #203 (docs/roadmap/new-acp-adapter.md). Changed in #310: ACP agents take cards, as main runs them.

One adapter runs any agent on `agent/acp-agents.ts`, the only source of an ACP command, so one not
on it is never linked or run. An entry must name the args or environment that make the agent skip
the owner's settings and MCP servers, with a dated check; the list-shape test refuses one without,
unless the owner is warned instead (D-134). The agent starts at a session's first turn and keeps
running for its later turns, each a `session/prompt`, never in arguments. It ends 10 minutes after
a turn, with its session and with the daemon; a later turn resumes it. It ends a turn through
`submit_answer`, a tool of this program's `answer` subcommand, and WebChat checks the answer
against that turn's schema. Its permission requests get the rulebook's answer once
(`agent/rulebook.ts`), never `*_always`, and a question is a no. An ACP agent refuses a request
only when it is missing or older than its entry's minimum version, so it takes cards like any
linked harness.

Cost: an idle agent lives up to 10 minutes for each session. Its sandbox, shell and network are its
own, and the rulebook reaches only what it asks about. Nothing here was run against a real agent.
