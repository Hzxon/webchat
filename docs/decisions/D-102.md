### D-102: A conversation is a prompt and the messages that name it

Status: Accepted 2026-11-06 in #119 (R-035), changed in #131, #132 and #160. Changed in #310: harness sessions, hand overs (D-156) and own setup (D-157).

The owner talks with their agent in their direct chat. A prompt is a message whose sealed `prompt`
field names the project and, unless it links none, one of its repositories. Replies, cancels,
answers and failures name the prompt's client id, which its sender signs, unlike the server's
message id. The agent heeds only its owner's prompts, replies and cancels, in that direct chat, with
a signed send time within 10 minutes, once each (D-089, K-47). The agent answers from the named
repository's folder (D-094), and a reply it cannot place hears so. Each conversation is one session
of its harness (D-119) in a scratch copy: a repository of its own in the temp folder, holding one
commit of origin's default branch, so a turn moves none of the owner's branches and nothing from it
is pushed. Every turn fetches. When the branch moved, the copy moves to it and drops what the model
changed there, and the reply names both commits, so the model rereads the code instead of trusting
what it remembers. In the owner's own setup the session works in their folder as it stands, with no
copy and no fetch (D-157). A question about a board alone, or with no folder, runs in an empty
folder (R-038, D-103). A reply resumes the session, until its owner hands it to another harness
(D-156); turns run one at a time, and a cancel stops them. A long answer comes as messages of at
most 4,000 characters. A conversation left for 24 hours ends, and its copy goes. Why: the owner asks
from a phone, and the chat keeps it encrypted.

Cost: an answer waits up to 15 seconds for a check-in, plus the turn. Every turn fetches origin,
and a reply after a merge loses what the model changed in the copy. An answer cut inside a code
block shows as two messages.
