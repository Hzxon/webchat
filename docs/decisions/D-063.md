### D-063: A check fails a pull request that repeats a decision or roadmap id

Status: Accepted 2026-11-03 in #38. Changed in #310: main's ruleset requires the check.

The `doc-ids` workflow (`.github/workflows/doc-ids.yml`) runs on every pull request. It fails when
`docs/decisions.md` has two `### D-0xx:` headings with the same number, or `docs/roadmap.md` has two
`### K-n:`, `### R-nnn:` or `### Q-n:` headings with the same id. It is a few lines of `grep` and
`sort | uniq -d`, so it adds no dependency. The error names the file and the repeated id.

Why: sessions took "the next free number" in parallel, and git sees no conflict when the two
entries land in different places in the file.

Cost: the check sees only the pull request's merge with main at the time it runs. Main's ruleset
requires it on a branch that holds the newest main (D-076), so a pull request that fell behind runs
it again before it lands. Once the board gives every number (D-117), it guards hand edits only.
