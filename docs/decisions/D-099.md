### D-099: An agent refuses a second request for the card it runs

Status: Accepted 2026-11-05 in #115 (K-51), changed in #130 (R-037). Changed in #310: runs use the linked harnesses and the agent's own login.

An agent runs several cards at once, with no cap, each in its own worktree and harness session
(D-092, D-119), and each card once. A request from its owner for the card it is running fails at
once with "K-1 is already running.", and nothing starts: no run and no worktree. A copy starts no
run. A request for another card runs beside it. A round of fixes waits while its card runs. The
check follows the owner and send-time checks. A card is the board's doc and section, since two
projects can each have a K-1. A run that ended, however it ended, no longer counts, so the owner
runs the card again at once. Why: two tabs or two devices can each send before they sync, the
server cannot read which card a request names (D-014), so the agent catches the copy; and students
hand an agent several cards and expect them all to start.

Cost: five cards are five sandboxed harness sessions on one laptop and five drafts pushed with the
agent's GitHub login. A copy that reaches the agent after the first run ended runs as a request of
its own. A request in the same check-in as a cancel is refused, since the cancelled run has not
stopped yet.
