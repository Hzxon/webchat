### D-010: Migrations only grow at the end

Status: Accepted 2026-11-01 in 10ba6d8. Changed in #310: the list of migrations is the folder.

`SCHEMA` in `server/db/schema.ts` creates the original tables. Every later change is a numbered file
under `server/migrations/` (D-106). Each one runs once, in order, in a transaction that holds an
advisory lock, because several serverless instances can start at once. `webchat.meta` records how
many have run. The folder is the list: each file's name says what it adds. When two branches add
migrations, the one that reaches main first keeps its number, because a database that already ran
that number would skip the other.

Cost: a mistake in a migration on main is fixed with a new migration, never by editing the old one.
