### D-119: The owner names the harness in each request

Status: Proposed. Changed in #310 to the linked harnesses of D-152 and the hand over of D-156, as main has them; this takes the place of D-144's text.

An agent runs the harnesses its owner linked (D-152), unless the owner turned one off in Agent
settings (D-115). The owner names one, signed, in each card run and each prompt, as the repository
is named (D-093): a picker in the card's brief (D-105) and in the Ask box (`HarnessPicker`). It lists the harnesses of the agent's sealed setup answer and greys, with the
reason, one that cannot do what is asked, a card or a question. It preselects the last pick this
browser remembers, else the first that can. There is no stored or per-project default. A session
keeps its harness, so replies and fix rounds resume with it, until its owner hands it over (D-156);
a card run never moves. A request that names none, such as Check again (D-116) or a proposal's
draft (D-117), runs on the first linked harness. A request naming a harness the laptop lacks, or
one not linked or turned off, fails with the reason. The server learns nothing: the name travels
sealed, and the check-in's level names no harness. Why: a team on Codex or another harness could
not run an agent (R-043), and a pick per request keeps the server out of it.

Cost: a page that never opened Settings asks each agent for its setup once per load, a sealed
message in the direct chat. A reply after the owner turns the session's harness off fails instead
of moving on. With none linked, every request fails with the reason to link one.
